# Phase 11.4 — DEEPSTATE ML Model Retraining & Validation Report

---

## 1. Executive Summary

Phase 11.4 executes the **Controlled Candidate Model Retraining, Validation, Feature Importance Audit, Real IPsec OOD Benchmarking, and Domain-Shift Analysis** for the **DEEPSTATE IPsec VPN Security Intelligence Platform**.

Following the strict non-negotiable rules of Phase 11, experimentation was conducted without modifying or overwriting production artifacts (`data/models/final_model.pkl` and `data/models/preprocessor.pkl`). Candidate models were trained on the 5-class behavioral schema established in Phase 11.3 using 70/15/15 capture/session-level grouped splitting.

> [!CAUTION]
> **Final Promotion Decision: DO NOT PROMOTE CANDIDATE MODEL**
> **Verdict**: `MODEL RETRAINING BLOCKED — INSUFFICIENT LEGITIMATE TRAINING DATA`
>
> **Forensic Justification**: Candidate models trained on local synthetic development PCAPs (`SYNTHETIC_DEVELOPMENT`) demonstrate severe domain shift when evaluated against genuine IPsec StrongSwan testbed captures (`TEST-001.pcap`, `TEST-002.pcap`, `TEST-003.pcap`). The centralized Phase 11.3 UNKNOWN policy correctly flags **100% of real IPsec testbed flows as `UNKNOWN_UNCLASSIFIED`** due to classification confidence falling below the 50% threshold. Per Phase 11 rules, synthetic data must not be used to claim real-world performance, and candidate models must not be promoted without authentic training benchmarks.

## 3. Behavioral Target Schema & Feature Vector Specification

### 3.1 Target Schema (5 Behavioral Classes + 1 Safety Class)
1. `ICMP_DIAGNOSTIC` (mapped from synthetic ICMP flows)
2. `WEB_INTERACTIVE` (mapped from synthetic Web Browsing flows)
3. `BULK_TRANSFER` (mapped from synthetic File Transfer flows)
4. `STREAMING_MEDIA` (mapped from synthetic Streaming flows)
5. `VOIP_AUDIO` (mapped from synthetic VoIP flows)
6. `UNKNOWN_UNCLASSIFIED` (Safety Outcome for low confidence / low packet counts)

*Note: Legacy labels (`Chat`, `Email`, `P2P`) mapped to `UNKNOWN_UNCLASSIFIED` due to feature distribution overlap.*

### 3.2 Predictive Feature Vector ($X$)
The model consumes 28 predictive features ($X$) strictly decoupled from metadata/labels:
- **Volumetric**: `flow_duration_seconds`, `total_fwd_packets`, `total_bwd_packets`, `total_packets`, `total_fwd_bytes`, `total_bwd_bytes`, `total_bytes`, `packets_per_second`, `bytes_per_second`.
- **Length Statistics**: `pkt_len_mean`, `pkt_len_std`, `pkt_len_min`, `pkt_len_max`, `pkt_len_skewness`, `fwd_pkt_len_mean`, `bwd_pkt_len_mean`.
- **IAT Statistics**: `flow_iat_mean`, `flow_iat_std`, `flow_iat_min`, `flow_iat_max`, `fwd_iat_mean`, `bwd_iat_mean`.
- **Ratios**: `fwd_bwd_packet_ratio`, `fwd_bwd_byte_ratio`.
- **IPsec Context Flags**: `esp_packet_count`, `has_ike`, `has_esp`, `has_udp_4500`.

## 7. Real IPsec Out-Of-Distribution (OOD) Evaluation & Domain Shift Analysis

Candidate models were benchmarked against real StrongSwan IPsec testbed PCAPs (`TEST-001.pcap`, `TEST-002.pcap`, `TEST-003.pcap`) using `evaluate_real_ipsec_ground_truth()`.

### 7.1 Real IPsec OOD Results Table

| PCAP File | Real Ground Truth Profile | Target Behavioral Class | Candidate Inferred Class | Flow Count | Classification Confidence | Exact Match? | Triggered UNKNOWN Policy Reason |
|---|---|---|---|---|---|---|---|
| `TEST-001.pcap` | IKEv2/IPsec ESP ICMP Ping Burst | `ICMP_DIAGNOSTIC` | `UNKNOWN_UNCLASSIFIED` | 4 | 0.4210 (Max Prob < 0.50) | **NO** (UNKNOWN) | Confidence 42.1% below 50% threshold |
| `TEST-002.pcap` | IKEv2/IPsec ESP NAT-T Bulk Data | `BULK_TRANSFER` | `UNKNOWN_UNCLASSIFIED` | 4 | 0.3845 (Max Prob < 0.50) | **NO** (UNKNOWN) | Confidence 38.5% below 50% threshold |
| `TEST-003.pcap` | IKEv2/IPsec ESP NULL Web GET | `WEB_INTERACTIVE` | `UNKNOWN_UNCLASSIFIED` | 3 | 0.4412 (Max Prob < 0.50) | **NO** (UNKNOWN) | Confidence 44.1% below 50% threshold |

### 7.2 Domain-Shift Findings
1. **Packet Length Shift**: Real IPsec traffic adds +50–70 bytes of outer ESP headers, IV, SPI, and ICV authentication trailers. Models trained on unencapsulated synthetic PCAPs expect specific packet length means (e.g. 64B ICMP, 1460B HTTP) and fail to recognize ESP-encapsulated packet lengths.
2. **Burst & Volume Shift**: Real testbed PCAPs contain brief 3–4 packet bursts per flow, whereas synthetic PCAP generators produced sustained 200+ packet flows.
3. **Safety UNKNOWN Policy Functioning**: The centralized Phase 11.3 UNKNOWN policy worked as designed—preventing false positive classifications by forcing low-confidence real IPsec predictions to `UNKNOWN_UNCLASSIFIED`.

## 8. ESP Overhead Adaptation Analysis

- **Investigation**: Inspected raw packet parser logic (`backend/app/ml/flow_extractor.py`).
- **Finding**: Real IPsec payload data within ESP packets is encrypted using AES-CBC or AES-GCM.
- **Conclusion**: The inner packet length is **NOT legitimately observable** from outer header inspection without possessing the active IKEv2 SA encryption keys.
- **Policy Decision**: Per Section 12 directives, we **DO NOT fabricate** or subtract a hardcoded 50–70 byte offset. The limitation is explicitly documented.
